# Roadmap and known gaps

This page exists so that the boundary between *built* and *not built* is explicit. The
project rule is that nothing may be simulated, faked or estimated: an unbuilt capability
is labelled **PLANNED** here and in the UI, and a figure the platform did not measure is
shown as "no data" rather than as a number.

## PLANNED

| Capability | Current state |
| --- | --- |
| P95 authorization latency on the control-centre dashboard | The field exists and is `null`. There is no real measurement pipeline behind it, so the UI renders "no data" rather than a placeholder. Wiring it to OpenTelemetry histogram data is the intended next step |
| Redis as a hard dependency | Redis is optional by design (ADR-003). Caching, idempotency and rate limiting all fall back to PostgreSQL or in-process behaviour. A Redis-only fast path for the published-policy cache is not built |
| Separate module assemblies | Modules are folders inside one project sharing one `DbContext` (ADR-001). The boundary is enforced by convention and review, not by the compiler |
| Multi-region / active-active deployment | Single-region. `xmin` optimistic concurrency and the transactional policy-publish path assume one primary |
| SSO / external identity providers | ASP.NET Core Identity with local accounts only. OIDC/SAML federation is not implemented |
| Automated access-review remediation | Reviews produce Keep/Remove decisions and audit them; automatic revocation on a Remove decision is not wired |
| Benchmark results | `tests/Veritas.Benchmarks` compiles in CI but is never executed there. No benchmark numbers are published anywhere in this repository, because none have been measured on hardware that would make them meaningful |

## Known trade-offs, by design

- **`EnsureCreated` in Development.** It exists so `docker compose up && dotnet run` is a
  two-command experience. It is never used in Production, and it does not interoperate
  with migrations. See [database.md](database.md).
- **Migrations are not checked in.** A hand-written migration that drifts from the model
  snapshot fails silently, which is worse than no migration. They are generated by
  `scripts/generate-migrations.sh` and CI fails if the model has changed without one.
- **A single `DbContext` for 18 modules.** Simpler now, and a real cost if the team grows
  or a module needs independent schema evolution. ADR-001 records the reasoning.
- **Risk can only tighten.** A low risk score never rescues a deny. That is intentional
  and asymmetric on purpose.

## Deliberately absent

- **No inline scripts.** The CSP forbids them; the views contain none.
- **No GET logout.** Sign-out is a POST with an antiforgery token.
- **No policy expression language.** Policy input is structured data validated against a
  fixed attribute catalogue. There is no code path in which policy input is parsed as
  code, which is a constraint worth keeping even though it limits expressiveness.
- **No audit mutation.** No endpoint updates or deletes an `AuditLog` row, and the cleanup
  worker does not touch the audit table.
